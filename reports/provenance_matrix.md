## Checkpoint assumptions that remain unverified

- Advertised files and architecture are not proof of compatibility. There was no `torch.load`, model construction, renderer call, VAE encoding/decoding or policy inference in this gate.
- Run-specific training p, optimizer configuration, VAE/head revision alignment, image preprocessing, scalar-action conventions and relevant evaluation distribution must be linked to actual authorized checkpoint bytes in a later gate.
- The frozen release is a demonstration implementation; no complete paper evaluation harness, exact evaluation-query list, environment lock or all reproduction seeds were identified in the earlier audit. Do not assert that the public demo is necessarily the source used for paper plots.
- Generated input data use float32 in the release; this independent reference uses float64 deliberately. Exact support means all sign strings are enumerated, with floating-point error still checked rather than denied.
